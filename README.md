# PULSE / SLASH

Godot 4.6製、リズムに合わせて秘密の行動計画を作る1対1バトル。

## すぐ遊ぶ

- Windows：`build/windows/PulseSlash.exe` を起動。CPU戦はサーバー不要です。
- Web：プロジェクト直下で `./start-web.ps1`。ブラウザで http://localhost:8080 を開きます。Node.js 22以上が必要です。
- 編集：Godot 4.6で `project.godot` を開いてF6/F5。

## 対戦

1. 両者が同じサーバーのWeb版を開きます。
2. ホストが盤面・BPM・拍子を選び、ルーム作成 / 参加を押します。
3. 招待URLを相手に共有。相手も「ルーム作成 / 参加」を押すと開始します。
4. 設定は最初に入ったプレイヤーの値を採用します。3人目は参加できません。

対戦開始時は操作不可の4拍カウントが入り、1〜3拍目に `READY`、4拍目に強い音と `GO!` を表示します。その次の拍から最初の計画を受け付けます。

同じLANでは `http://サーバーPCのLANアドレス:8080/` を利用できます。インターネット越しでは公開サーバーに配置してください。`localhost` の招待URLは他のPCから接続できません。

## 操作とルール

|入力|動作|
|---|---|
|WASD|その方向へ1マス移動|
|矢印キーを短く押して放す|その方向へ通常攻撃|
|矢印キーを拍をまたいで長押し、拍上で放す|タメ攻撃|
|Shiftを押し続ける|全方向ガード|
|Shiftを放す|ガードを解除|
|Escape|退出してメニューへ|

- ライフ3、必殺ゲージ3、ゲージ上限3。全攻撃は1ダメージ。残りライフ1になると、自分と相手のどちらの四角も白く点滅します。
- 1小節の計画→専用音と演出の1拍→1小節の行動→次の計画への1拍を繰り返します。1ターンはこの1組です。両方の切り替えの1拍は入力・攻撃・移動を行いません。計画へ戻る1拍は青色の背景・収束するリングと菱形・低めの和音で知らせます。
- 拍子は1〜32拍。`3` / `5` / `3+2` / `2+2+3` など。`+` の区切りで強拍が鳴ります。分母は共通の1拍単位で、BPMはこの拍の速度です。
- BPMは20〜400。判定幅は前後130msと1拍の28.6%の小さい方（初版より30%拡大）。入力補正は±250ms。
- 1拍に1行動。計画中は自分の半透明の分身と行動列だけが変化し、相手の計画は見えません。
- 行動ターンでは双方の移動を先に処理し、攻撃を同時判定します。同じ場所への移動と位置交換は双方とも失敗。相打ちで両者0なら引き分けです。

### タメ

|タメ拍数 / ゲージ消費|範囲|
|---|---|
|0|前方1マス|
|1|前方直線2マス|
|2|前方1マス＋自分の左右1マスずつ|
|3|前方直線2マス＋斜め前2マス|

通常攻撃は拍に合わせて押せていれば、次の拍のタメ判定に入る前に放すタイミングは自由です。最後の拍は押したまま小節が終わっても通常攻撃になります。タメ・ガードの保持中にはそれぞれ異なる継続音が鳴り、タメは拍が進むにつれて音が高くなります。タメ攻撃またはガードを拍上で正しく解除すると、成功を知らせる明るい和音が重なります。

4拍子では1拍目に押し、4拍目に放すと3拍タメ。その小節は移動できません。3拍子では2拍タメまで。タメは小節を持ち越しません。タメ攻撃は入力開始と解放が拍に合う必要があり、タメ始めてから拍を外して放す、ゲージ不足、小節内に放さない場合は不発・ゲージ消費なしです。成立した攻撃は空振りでも消費します。

### ガードと回復

ガード開始は拍に合わせます。保持中は毎拍の入力不要。解除した拍からガードがなくなります（押したのと同じ拍で解除した場合、その拍のガードは残ります）。拍上の解除は次の1ターン、拍から外れた解除は次の3ターン使用不可。小節をまたいだ保持は小節末に自動解除し、1ターン休止します。

各行動ターン後、30%で空きマスに回復アイテムを生成。双方からのマンハッタン距離の差が最小の候補からランダムに選びます。拾うとゲージ+1、最大3。マップ上には最大1つだけ存在し、新しいアイテムが生成されると前のものは消えます。生成されなかったターンは既存のアイテムが残ります。

### 対戦画面の図形

- ミント色＝自分、赤＝相手。丸3つ＝ライフ、黄色の菱形＝必殺ゲージ。
- 盾＝ガード、横の小さな丸＝再使用までの残りターン。
- 青緑の背景＋「計画」＝計画、赤紫の背景＋「行動」＝実行。間の1拍は金色の背景・広がるリング・矢印と専用の和音で切り替えを知らせます。並んだ丸が拍の位置、強い点灯が強拍。
- 下の列＝自分の計画。矢印＝移動／攻撃、黄色い輪＝タメ、盾＝ガード。
- 画面端の赤い点滅と×＝入力失敗／空白の拍。被弾は白い点滅と揺れ。

## 公開サーバーへの配置

WebファイルとWebSocketを単一のNode.jsサーバーで配信します。WebSocketアップグレード対応のホスティングに配置してください。

```sh
docker build -t pulse-slash .
docker run --rm -p 8080:8080 pulse-slash
```

Dockerを使わない場合は `server` で `npm ci && npm start`。`PORT` 環境変数でポート変更。HTTPSのリバースプロキシで `/ws` のWebSocket Upgradeを転送します。Web版はページのホストから接続先を自動設定し、HTTPSではWSSを使います。

公開先の契約・DNS・証明書設定は含まれていません。生成されたビルドはローカルサーバーで確認済みです。

## 通信設計と制約

- サーバー時刻へのオフセットを低RTTのpingから推定。拍の判定は端末側で即時実施。
- 計画小節の終了時に計画を提出。最後の拍の通常攻撃も余裕を持って放せます。サーバーは小節終了から0.4拍後に提出を締め切り、切り替えの1拍を挟んで行動を開始します。戦闘結果はサーバーで計算し、計画中の逐次入力は相手に送信しません。
- 行動開始時刻と各拍のスナップショットを双方へ一括配信。遅着時は現在の拍まで追いつきます。
- 通信が提出締切に間に合わない場合、その小節は待機として扱います。常に約1拍以上の遅延がある接続には不向きです。
- サーバーは方向、行動数、タメに使う拍数、ゲージ、ガード使用可否を検証します。端末での実際のキー入力時刻の不正検出は未実装です。競技向けの完全なアンチチートはありません。
- ルームはメモリ保存。切断で対戦終了、再接続／観戦／途中参加はありません。再戦はメニューから同じルームを作り直します。
- PCキーボード向け。スマートフォン用のタッチ操作は未実装。

## ビルド・検証

`./build.ps1` でWeb／Windowsを出力。Godot 4.6と同版の公式エクスポートテンプレートが必要です。

```sh
node --test --test-isolation=none tests/rules.test.mjs
# サーバー起動中に実施
node --test --test-isolation=none tests/network.test.mjs
Godot --headless --path . --script tests/input_test.gd
```

`scripts/rules.gd` はCPU戦用の純粋な戦闘処理、`server/rules.mjs` は通信戦用。`scripts/main.gd` は入力・描画・拍同期、`server/index.mjs` は配信とルーム管理です。
